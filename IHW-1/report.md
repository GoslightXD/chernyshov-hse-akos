## 1. Условие задачи
Племя из нескольких дикарей питается из общего горшка ограниченной вместимости. Когда дикарь хочет есть, он забирает из горшка одну порцию. Если горшок пуст, первый обнаруживший это дикарь будит повара и ожидает наполнения; остальные голодные дикари тоже ожидают, не создавая повторных запросов. Повар наполняет пустой горшок установленным количеством порций и снова засыпает. Наполнение не начинается, пока в горшке остаются порции. Источник порций можно ограничить общим запасом.

Требуется разработать консольное приложение, моделирующее совместный обед племени.

**Входные параметры:** количество дикарей; вместимость горшка; число приёмов пищи каждого участника; диапазоны времени между приёмами пищи; продолжительность приготовления; общий запас порций (если ограничен).

**Отображаемые события:** попытка получить порцию, число оставшихся порций, обнаружение пустого горшка, пробуждение повара, начало и окончание приготовления, наполнение горшка, получение порции, завершение питания участника.

**Инварианты:** число порций в диапазоне [0, вместимость]; одну порцию получает не более одного дикаря; одновременно горшок наполняет только повар; одно опустошение порождает не более одного актуального запроса повару; повар не перезаполняет непустой горшок.

**Завершение:** после выполнения заданного числа приёмов пищи; либо после исчерпания ограниченного запаса с корректным завершением ожидающих; либо по прерыванию пользователем в режиме неограниченного по времени выполнения. Повар и каждый дикарь — самостоятельные участники модели.

## 2. Сценарий: отображение сущностей на программные конструкции
Программа — **последовательная** (один процесс, один поток), дискретно-событийная имитация с виртуальным временем.

| Предметная сущность | Конструкция в программе |
|---|---|
| Входные параметры | `struct Config` |
| Горшок, запас, счётчики запросов | `struct World` (`pot`, `supply_left`, `request_pending`, `empties`, `requests`, ...) |
| Дикарь | `struct Savage` (состояния `S_IDLE`, `S_WAIT_COOK`, `S_DONE`, `S_STARVED`), поведение — функция `savage_act()` |
| Повар | `struct Cook` (состояния `C_SLEEP`, `C_COOKING`), поведение — функция `cook_finish()` |
| Инварианты | функция `check_invariants()`, вызывается после каждого события |
| Условия завершения | цикл в `simulate()`, флаг `g_stop` (SIGINT), `print_stats()` |

**Как работает планировщик.** У каждого участника есть момент следующего действия (у дикаря `next`, у повара `end`). На каждом шаге выбирается ближайшее событие, виртуальное время переводится на его момент, выполняется действие. При равенстве времён первым выполняется повар, затем дикарь с меньшим номером. Случайные величины (интервалы между приёмами пищи, длительность приготовления) берутся из `rand()` с настраиваемым seed.

**Логика дикаря.** В момент голода он пытается взять порцию. Если порция есть, он берёт её и либо завершает питание (достиг заданного числа приёмов), либо планирует следующий приём. Если горшок пуст, он фиксирует обнаружение пустого горшка. Если запроса повару ещё нет (`request_pending == 0`), дикарь будит повара, иначе просто ждёт, не создавая повторного запроса. Если запас порций исчерпан, дикарь уходит голодным (корректное завершение ожидающих).

**Логика повара.** Спит, пока его не разбудят. После пробуждения готовит случайное время из заданного диапазона, затем кладёт в горшок min(вместимость, остаток запаса) порций, сбрасывает запрос, засыпает и будит ожидающих дикарей: столько, сколько положено порций, в порядке очереди (кто ждёт дольше, тот первый). Остальные продолжают ждать и повторных запросов не создают. Дикарь, взявший последнюю порцию, будит следующего в очереди: тот обнаруживает пустой горшок и делает новый запрос (одно опустошение — один запрос). Если запас исчерпан, ожидающие по цепочке просыпаются и уходят голодными.

**Начальное состояние:** горшок пуст, повар спит (это считается первым опустошением).

## 3. Пользовательский интерфейс
Консольное приложение для Linux. Весь вывод идёт через `write(2)` одновременно на экран и в журнал, каждая строка имеет вид `[t=  12] Дикарь 3: получил порцию #1, в горшке осталось 1`, то есть наблюдатель видит время и событие в терминах предметной области. Реальные задержки (`-d`) делают ход обеда наглядным.

Способы задания параметров:
1. Аргументы командной строки: `-n` дикарей, `-c` вместимость, `-m` приёмов пищи (0 = бесконечно), `-t MIN:MAX` интервал между приёмами, `-k MIN:MAX` время приготовления, `-s` запас порций (0 = не ограничен), `-r` seed, `-d` задержка в мс на единицу времени, `-l` файл журнала, `-i` интерактивный режим, `-h` справка.
2. Интерактивный ввод — при запуске без аргументов или с `-i` (Enter = значение по умолчанию, ввод проверяется).
3. Некорректные параметры отвергаются с сообщением, код возврата 1.

## 4. Варианты запуска и завершения
| Запуск | Завершение | Код |
|---|---|---|
| `./cannibals -n 5 -c 4 -m 3` | все дикари получили заданное число порций | 0 |
| `./cannibals -n 4 -c 3 -m 5 -s 7` | запас исчерпан, ожидающие дикари корректно уходят голодными | 0 |
| `./cannibals -m 0` (запас не ограничен) | работает бесконечно, остановка по Ctrl+C: обработчик SIGINT выставляет флаг, программа печатает статистику и закрывает журнал | 130 |
| неверные параметры | сообщение об ошибке | 1 |
| нарушение инварианта (не должно происходить) | сообщение и аварийное завершение | 2 |

Из-за детерминизма по seed (`-r`) запуск с теми же параметрами воспроизводит тот же журнал. В конце работы выводится статистика (число наполнений, время работы повара, число опустошений и запросов, баланс порций, порций/ожидание каждого дикаря) и записывается в `cannibals.log`.

## 6. Тестирование
Скрипт `tests/run_tests.sh` собирает программу и проверяет: обычный запуск, 1 дикаря, большой горшок, 200 дикарей, нулевые интервалы, ограниченный запас (исчерпание и достаточный запас), воспроизводимость по seed, неверные параметры, прерывание по SIGINT, интерактивный ввод. Результат: 15 из 15 тестов пройдено. Отдельно проверено 200 дикарей при горшке на 3 порции: около 7,7 тыс. строк вывода, время работы доли секунды.
